Frequently Asked Questions

What metadata does a PDF contain?
Title, author, subject, keywords, the software that created it, and the creation and modification dates. Depending on how the file was produced it may also carry the original file path, the organisation name from the software licence, and traces of earlier revisions.
Why should I care about metadata?
Because it travels with the file and is trivially visible to anyone who opens the document properties. Author fields have exposed who really wrote an anonymous document, and file paths have revealed internal folder structures and staff names. It has caused genuine problems in published documents.
How do I see the metadata in a PDF?
Any PDF reader shows it under document properties or file information. In Acrobat and most browsers it is a menu option; on macOS Preview it is under Tools. It takes one click, which is exactly why leaving sensitive values in place is risky.
Can I clear the metadata entirely?
Yes. Fields can be emptied so the document carries no author, title, or software information. This is worth doing routinely for anything being published or sent outside your organisation.
Does editing metadata change the document content?
No. Metadata is stored separately from the page content. Every page, font, and image is completely untouched — only the descriptive information about the file changes.
Does clearing metadata make a document anonymous?
It removes one significant source of identifying information, but not all of them. The page content itself may identify the author through writing style, embedded images may carry their own EXIF data, and Redact PDF is needed for anything identifying in the visible text.

What Metadata Is and Why It Matters

Every PDF carries a set of descriptive fields that are not visible on any page but travel with the file wherever it goes. Anyone can view them in a couple of clicks through their PDF reader's document properties panel.

These fields routinely contain more than people realise. The author field is usually filled automatically from the licence name on whoever's copy of Word or Acrobat produced the file. The producer field records the exact software and version. Depending on how the document was created, the metadata may also include the full file path it was saved from — which can expose internal folder structures, project code names, and staff names.

There is a long history of documents being published with author fields that contradicted their stated origin. It is a small detail that has caused disproportionate embarrassment.

Why Set Metadata Properly

Findability. Document management systems, corporate search, and desktop search all index metadata. A file with a meaningful title and relevant keywords surfaces when someone searches for it; one with an empty title and an author field reading "Administrator" does not.

Presentation. The title field is what most PDF readers display in the window title bar and browser tab — not the file name. A document with no title shows the file name instead, which frequently looks like final_v3_REVISED_2.pdf and does not inspire confidence.

Consistency. Documents that will be archived or catalogued benefit enormously from consistent metadata, and retrofitting it later across hundreds of files is painful.

Why Clear Metadata

Before publishing anything. A document going on a website or into a public filing carries whatever metadata it accumulated during production, including the name of everyone whose software touched it.

When anonymity matters. Anonymous submissions, blind peer review, and confidential reports are all undermined by an author field naming the writer.

When the origin should not be visible. A document produced for a client using an internal template may carry the internal project name in the subject field or the folder path in the producer information.

As routine hygiene. Clearing metadata before external distribution costs seconds and removes an entire category of accidental disclosure.

Who Uses This Tool

Publishers and web teams set proper titles and clear internal author names before documents go live. Researchers strip identifying fields before submitting for blind review. Legal teams clear metadata on documents being disclosed or filed. Agencies remove internal project references from client deliverables. Anyone archiving documents adds consistent titles and keywords so files can be found later.

Edit the fields you want to change or clear the ones that should not travel with the document, then download the updated file.

The Page Content Is Untouched

Metadata is stored in a separate part of the file from the page content. Changing it does not affect a single page, font, or image. The document looks and behaves exactly as before, and the file size barely changes. This makes metadata editing completely safe to run on any document.

Clearing Metadata Is Not the Same as Anonymising

Worth being clear about, because it is easy to overestimate what this achieves. Removing the author field removes one identifier. It does not remove names, addresses, or other identifying information from the visible page content — for that you need Redact PDF. It also does not remove EXIF data embedded inside photographs within the document, which can include camera details and sometimes GPS coordinates.

For genuine anonymisation, treat metadata clearing as one necessary step among several rather than the whole job.

Your Privacy Is Protected

Your document is processed in memory and discarded the moment your download completes. Nothing is written to disk, nothing is logged, and no copy is retained.
