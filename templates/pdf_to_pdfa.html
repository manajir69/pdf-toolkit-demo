Frequently Asked Questions

What is PDF/A and how is it different?
PDF/A is a restricted version of PDF designed for long-term archiving. It requires everything needed to display the document to be contained inside the file itself, and forbids features that depend on external resources or that may not be supported decades from now.
Why does archiving need a special format?
Because an ordinary PDF can reference fonts installed on the computer opening it. That works today and fails in twenty years when the font no longer exists, causing substitution and layout shifts. PDF/A embeds everything so the document renders identically regardless of what is installed.
What is not allowed in PDF/A?
JavaScript, embedded audio and video, encryption, external content references, and non-embedded fonts. Each is excluded because it either depends on something outside the file or cannot be guaranteed to work in the distant future.
Will my document look different after conversion?
It should look the same. Conversion embeds what was previously referenced and removes features that were not part of the visible content anyway. Check the result, particularly if the original used unusual fonts.
Who needs PDF/A?
Anyone with a retention obligation — courts, government bodies, universities, libraries, medical records departments, and regulated industries. Many require PDF/A specifically for submissions, and it is a sensible default for anything that must remain readable for decades.
Can PDF/A files be password-protected?
No. Encryption is prohibited by the standard, because a password protecting an archive is a password that will eventually be lost. Store PDF/A files in a secure location rather than encrypting them individually.

What PDF/A Actually Solves

An ordinary PDF is allowed to depend on things outside itself. It can reference a font installed on the reader's computer rather than embedding it. It can link to external content. It can contain JavaScript, embedded media, and features that only certain software understands.

All of this works today. The problem is the timescale of archiving. In twenty years the referenced font may not exist on any current system, the linked content will almost certainly have moved or vanished, and the software that understood a particular feature may no longer be made. The document opens, but it does not look the way it did — text reflows because a substitute font has different metrics, images are missing, and the layout that carried the meaning is gone.

PDF/A eliminates the dependencies. Everything required to display the document exactly as intended must be contained within the file. Nothing external, nothing conditional, nothing that requires a particular piece of software.

What the Standard Requires and Forbids

Fonts must be embedded. Every typeface used is included in the file, so text renders identically regardless of what is installed on the machine opening it. This is the single most important requirement and the one that prevents the most common form of archival degradation.

Colour must be unambiguous. Colour profiles are embedded so that colours reproduce consistently rather than being interpreted differently by different systems.

JavaScript is prohibited. Executable content is a security concern and a dependency on an interpreter that may not exist in the future.

External references are prohibited. A document that depends on something it does not contain is not self-sufficient.

Audio and video are prohibited. Media codecs change and the format cannot guarantee they will remain playable.

Encryption is prohibited. A password protecting an archive is a password that will eventually be lost, taking the document with it.

Who Needs PDF/A

Courts and legal filing systems frequently mandate PDF/A for submissions. Government departments require it for records subject to retention schedules. Universities specify it for thesis and dissertation deposits. Libraries and archives use it as their standard preservation format. Medical records departments rely on it for documents that must remain readable for decades. Regulated industries — pharmaceutical, financial, aerospace — use it for compliance documentation with long retention requirements.

Beyond formal requirements, it is a sensible default for anything genuinely important: contracts, certificates, deeds, and records you expect to need long after the software that created them is obsolete.

File Size Will Increase

This is expected and not a fault. Embedding complete font files adds to the file size, sometimes substantially for documents using several typefaces. It is the direct cost of self-sufficiency, and for an archival document it is the right trade — a larger file that renders correctly in 2050 is worth considerably more than a smaller one that does not.

Do not compress a PDF/A file afterwards, as compression may strip the embedded resources the standard requires and break compliance.
