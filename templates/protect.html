Frequently Asked Questions

What kind of encryption is used?
The PDF is encrypted using the AES standard built into the PDF specification. Without the password the file contents cannot be read — this is genuine cryptographic protection, not a flag that a reader politely obeys.
What happens if I forget the password?
The document cannot be opened. There is no recovery mechanism and no back door, which is exactly what makes the encryption worth using. Store the password somewhere safe before you send the file, and never inside the same email as the attachment.
Should I send the password in the same email?
No. Putting the file and its password in one message defeats the entire purpose — anyone who intercepts the email gets both. Send the password through a different channel: a phone call, a text message, or a separate messaging app.
Can I remove the password later?
Yes, provided you know it. Our Unlock PDF tool strips the encryption from a document you can already open, returning an unprotected version.
Does protecting a PDF change how it looks?
No. Encryption operates on the file's data, not its appearance. Every page, font, and image is exactly as it was — the only difference is that a password is required before any of it can be displayed.
Are my files or passwords stored on your server?
No. The document is processed in memory and discarded the moment your download completes, and the password is used only for that single operation. Nothing is written to disk, nothing is logged, and no copy is kept.

Why Password-Protect a PDF?

Documents travel further than we intend. An email gets forwarded, a file lands in a shared folder that more people can reach than expected, a laptop is left on a train. Encryption means that in all of those cases the contents stay unreadable to anyone without the password.

It also matters for compliance. Financial records, medical information, employee data, and client details all carry obligations about how they are handled, and encrypting a file before sending it is one of the simplest ways to meet the basic standard of care.

This Is Real Encryption

Worth being precise about, because PDFs support two very different things that both get called protection.

Permission flags tell a reader that printing or copying should be disallowed. They are requests. The file is not encrypted, the content is fully readable, and any tool that chooses to ignore the flag simply does.

Password encryption — what this tool applies — scrambles the file's actual contents. Without the password there is nothing to read, whatever software you point at it. The document is genuinely protected rather than politely marked.

Choosing a Password That Helps

The encryption is only as strong as the password guarding it, and short passwords fall quickly to automated guessing.

Length beats complexity. A passphrase of several unrelated words is both easier to remember and harder to break than a short string of substituted symbols. Aim for at least twelve characters.

Do not reuse a password you use elsewhere, particularly not one attached to an email or bank account.

Avoid anything guessable from context — the company name, the project name, the current year, or the recipient's surname are all poor choices precisely because they are the first things anyone would try.

Never Send the Password With the File

This is the most common mistake and it undoes everything. If the encrypted PDF and its password arrive in the same email, anyone who reads that email has both. Use a different channel entirely: phone the recipient, send a text message, or use a separate messaging app. The two pieces should never travel together.

There Is No Password Recovery

If the password is lost, so is the document. This is not a limitation we could remove — a recoverable password would mean a back door, and a back door means the encryption protects nobody. Save the password in a password manager or write it somewhere secure before you close the tab. This is genuinely the most common way people lose access to their own files.
